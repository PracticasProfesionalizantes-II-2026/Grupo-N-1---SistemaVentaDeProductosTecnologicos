## Preparación de la exposición

Abrir el PowerPoint en modo presentador y Recorrido-TotalTech.html en una ventana aparte. Tener las fuentes de cada caso abiertas en el editor. Usar un entorno de demostración aislado, con una cuenta ficticia de cliente y una sesión administrativa separada. No usar datos de producción. Este paquete no crea cuentas ni modifica bases de datos.

Preparar un email ficticio único, por ejemplo exposicion.totaltech@example.com; usar la contraseña de demostración elegida por el equipo sin proyectarla. Preparar una categoría, un proveedor activo y productos suficientes para demostrar paginación. El producto Notebook exposición TotalTech tendrá precio 125000 y stock 5, que se editará a 7. Solo eliminar ese producto si no tiene relaciones. Usar una imagen PNG real menor de 5 MB.

Al empezar, pulsar Iniciar en el temporizador. Si una acción supera su ventana, volver a la diapositiva y explicar el flujo o usar la captura disponible. Decir “este es el resultado esperado según el código” cuando no se haya observado el resultado en vivo.

### 11. Recorrido de una solicitud

**Facundo · 14:15–16:00 · 1:45**

105 s. Seguir ida de izquierda a derecha y vuelta en sentido inverso. Abrir HTML solo si ya está preparado.

**Intervención sugerida**

Tomemos la búsqueda del catálogo como ejemplo completo. El navegador envía los filtros definidos por la vista Razor al controlador MVC. El controlador coordina la operación y delega la comunicación en ProductosApiService. El cliente HTTP llama al endpoint de productos. El endpoint recibe el contrato y la lógica valida las reglas antes de consultar el repositorio. El repositorio utiliza Entity Framework y TotaltechDbContext para llegar a SQL Server. La respuesta vuelve por esas capas: los resultados se proyectan en un DTO, la API lo serializa como JSON, el servicio del frontend lo deserializa y MVC construye el modelo de pantalla. Finalmente Razor produce el HTML que recibe el navegador. Esta separación permite ubicar una falla: validación de pantalla, comunicación, regla de negocio o persistencia. Hay dos particularidades que vimos: registro y login llaman directamente a IHttpClientFactory desde HomeController; algunas escrituras del carrito usan DbContext dentro de la lógica.
